# 공명자 도트 제작 절차

## 규격
| 항목 | 기준 |
|---|---|
| 비율 | 7등신, 치비 금지 |
| 원본 시트 | 4열×2행. 1행 대기·준비·공격·회복, 2행 방어·피격·시전·해방 |
| 원본 크기 | 칸 높이의 72%, 8칸 동일. 발 높이 동일 |
| 게임 프레임 | 공명자 320×320(몸 208px + 이펙트 여백), 투명 배경, 오른쪽 방향. 적은 128×128 |
| 몸 크기 | 대기 자세 208px, 메카 184px (`prepare-heroes-v3.cjs`) |
| 색 | 프레임 48색(공명자·카드), 배경 64색, 디더링 없음. `lib/pixel.cjs`의 `limitColors`로 줄이고 8비트 팔레트로 저장한다. sharp 0.33의 `png({colours:48})`는 색 수가 아니라 비트 깊이만 정해 16색으로 깎으므로 쓰지 않는다 |
| 표시 크기 | 공명자 320px×`--k`(정수 배율). 적 128px 프레임은 2배. 일반 적은 재제작 전까지 192px(1.5배, 부드럽게), 정예 256px, 보스 384px, 벤치 0.5배 |
| 공격 모션 | 5칸: 준비 → 베기 3칸 유지 → 회수(8fps). 베는 칸이 125ms에 나와 피해 숫자(170ms)와 맞음 |
| 대기 모션 | 정수 픽셀 이동만. 회전·미세 확대 금지 |
| 전투 배경 | 640×360 도트 격자(블록 최빈색, 64색), `scripts/prepare-battle-bg.cjs`. 화면을 덮는 최소 정수 배율로 최근접 확대(1080p 3배, 4K 6배). 프롬프트는 [BG_PROMPTS.md](BG_PROMPTS.md) |
| 해상도 | 캐릭터는 실제 화면 높이 1000px당 1배 정수 배율(1080p 1배, 4K 2배, 레티나는 최소 실제 2배). `input.js`의 `pixelScale()`이 `--k`·`--bk`를 정함 |
| 축소 | 블록 최빈색(lanczos 대신). 가짜 도트 원본의 윤곽선을 흐리지 않음 |
| 칸 넘침 | 칸 밖 22% 여백까지 읽고, 무게중심이 이 칸 안에 있는 덩어리만 남김(옆 칸으로 넘어간 베기를 되살림). 몸은 칸 중심 기준으로 고정 |
| 다듬기 | 축소 때 어두운 선(블록의 20% 이상, 최빈색보다 확실히 어두움)을 우선 남기고, 실루엣 바깥에 1px 남색 윤곽선(#121426)을 그림 |
| 잘린 단면 | 실제로 잘린 변(원본 읽기 영역·320 프레임 경계에 닿은 변)에 8px 이상 일자로 닿은 이펙트만 물결 모양으로 깎음(`taper`, 깊이 칸의 9%). 발 쪽은 제외 |
| 스킬 임팩트 | `scripts/make-vfx.cjs`가 코드로 찍음. 64×64 6프레임, 속성당 4색, 화면 2배(치명·큰 피해 3배) |
| 칼베기 | `art/fx-src/`의 CC0 원본을 `make-vfx.cjs`가 속성 팔레트로 칠함. 64×47 9프레임, 화면 3배(큰 공격 4배). 외부 에셋은 CC0만 쓰고 출처를 그 폴더 README에 적는다 |
| 카드 | 144×96. 칸 안쪽 6px을 잘라 줄임 |

## 절차
1. [CHARACTER_BIBLE.md](../lore/CHARACTER_BIBLE.md)에서 설정과 무기를 확인한다. 없으면 먼저 추가한다.
2. [HERO_PROMPTS.md](HERO_PROMPTS.md)의 프롬프트에 공식 이미지와 `art/source-v2/hero_mor.png`(승인된 비율 기준)를 순서대로 첨부해 생성한다.
3. 결과를 `art/source-v2/hero_<id>.png`, `cards_<id>.png`로 저장한다.
4. `scripts/prepare-heroes-v3.cjs`의 `HEROES`에 id를 넣는다.
5. `IDS=<id> node scripts/prepare-heroes-v3.cjs preview`로 `art/preview-v3/`에서 먼저 본다.
6. 문제없으면 `IDS=<id> node scripts/prepare-heroes-v3.cjs write`로 적용한다. `IDS`를 빼면 전원을 처리한다. 카드 시트(`cards_<id>.png`)를 다시 자를 때만 `CARDS=1`을 붙인다(단품 카드 `art/card-gen/`을 덮어쓰므로 끝나면 `node scripts/cards.cjs import`).
   - `hero_<id>_full.png`(16칸, [프롬프트](HERO_PROMPTS.md))가 있으면 8칸 시트 대신 그것을 쓴다. 대기 숨쉬기 2장, 동작은 8장 스트립을 16fps로 재생한다.
7. 게임 화면에서 대기·공격·해방을 확인한다.

## 검수 항목
- [ ] 칸 수가 맞고 경계를 넘은 부분이 없다
- [ ] 7등신이고 8칸의 몸 크기가 같다. 해방 칸에서도 작아지지 않았다
- [ ] 얼굴·머리·의상·무기가 8칸 모두 같고 공식 이미지와 맞다
- [ ] 무기가 [설정 기준표](../lore/CHARACTER_BIBLE.md)와 맞다
- [ ] 진짜 투명 배경이고 글로우 번짐·잡티가 없다
- [ ] 글자·숫자·테두리가 없다

## 주의
- `prepare-sprites.cjs`, `prepare-art-v2.cjs`는 새 도트를 덮어쓰므로 막아 두었다. 쓰지 않는다.
- 공식 이미지는 커밋하지 않는다.
- 이전 디자인 원본(`art/source/`의 공명자 시트, `heroesA/B`)은 방랑자·파수인·치사·카멜리아 교체가 끝나면 지운다. 그 전에 지우면 재처리가 불가능하다.

## 에셋 보드
지금 게임에 들어간 그림을 보고, 필요할 때 프롬프트를 열어 복사하고, 새 그림을 넣기 전에 비교해서 고르는 화면이다(예전 리뷰 화면 `art/review.html`을 합쳤다). 그림을 사람이 직접 보고 고르므로 에이전트가 이미지를 열 필요가 없다.

- **에셋 탭**(처음 화면): `assets/`의 모든 공명자·적을 카드로 보여 준다. 동작(대기·공격·방어·피격·시전·해방)을 골라 재생하고 전투 배경을 바꿔 본다. 공명자는 [설정 기준표](../lore/CHARACTER_BIBLE.md)의 속성·무기·소속·서사·외형·근거를 같이 보여 준다(없으면 미확인). **프롬프트 보기**를 펼치면 그 캐릭터 키(`hero_<id>`, `_full`, `_extra`, `cards_<id>`, `enemy_full_<id>`)의 프롬프트를 복사하고, **후보 비교**로 GPT 탭의 그 항목으로 간다. 아래에 카드 일러스트와 지역 배경.
- **GPT 시트·PixelLab 탭**: 프롬프트 전체 목록(아래 절차).
- 공명자 시트 프롬프트에는 `PROPORTION LOCK`(7등신, 대기 키 = 칸 높이 72%, 같은 발 선, 첨부한 다른 공명자와 같은 머리 크기·키)이 자동으로 붙는다. `scripts/lib/clean-lock.cjs`가 넣고, 메카는 사람 비율이 아니라 뺀다. 16칸 시트(`hero_<id>_full`)에는 첨부 3 비율 가이드 `art/guides/hero-16-guide.png`(`node scripts/make-guides.cjs`로 만듦: 파란 선 머리 꼭대기·빨간 선 발바닥·맨 위 띠 머리 1/7·점선 여백 12%)를 맞추라는 문장도 붙는다. GPT는 대화마다 이전 결과를 기억하지 못해 숫자만으로는 비율이 달라지므로, 매번 같은 그림을 붙여 맞춘다. 외형의 기준은 첨부 1 명조 공식 이미지이고, 지금 도트는 도트 밀도·크기 기준으로만 쓴다.

1. `npm run board` — `art/board.html`을 만들고 연다. 프롬프트 내용은 [REVISION_PROMPTS.md](REVISION_PROMPTS.md), [HERO_PROMPTS.md](HERO_PROMPTS.md), `art/card-prompts.md`에서 가져온다.
2. 항목의 **프롬프트 복사**를 눌러 이미지 생성에 붙여 넣는다. 칸에서 고친 내용은 그 브라우저에만 남는다. 계속 쓸 수정은 원본 문서에 반영한다.
3. 만든 그림을 `art/candidates/<키>/`에 아무 이름으로 넣는다. 키는 항목 제목 옆에 있다(예: `hero_aem`, `aem_a`). 여러 장을 넣어도 된다.
4. `npm run board`를 다시 실행하면 지금 쓰는 그림 옆에 후보가 나란히 보인다. 두 번 누르면 크게 보인다.
5. 고를 후보를 누르면 아래에 적용 명령이 나온다. 복사해서 실행하면 원본 자리(`art/source-v2/` 또는 `art/card-gen/`)에 들어가고, 다음에 돌릴 명령을 알려 준다. 고르지 않은 후보는 게임에 영향을 주지 않는다.

보드와 후보 폴더는 저장소에 넣지 않는다.

## 생성 도구별 차이 (사용자 경험, 2026-11-23)
| 도구 | 잘하는 것 | 문제 | 대응 |
|---|---|---|---|
| GPT 이미지 | 첨부 그림을 따라 캐릭터 외형 유지 | 정보가 많으면 자글자글해지고 뭉개짐(반짝이·반투명 겹침·잔상·배경 큰 얼굴) | 모든 GPT 프롬프트 끝에 `CLEAN LOCK` 문장(`scripts/lib/clean-lock.cjs`). 문서 고친 뒤 `node scripts/lib/clean-lock.cjs`, 카드·모션은 생성 스크립트가 자동으로 넣음 |
| 구글 플로우(나노바나나) | 자글거림이 적고 배경을 여러 장 뽑기 쉬움 | 캐릭터 완성도가 낮음. 한국에서는 보이는 워터마크가 자동으로 붙음(구글 도움말 인용 기사, 원문 미확인) | 배경 위주로 쓰고, 모서리에 중요한 것을 두지 않음. 워터마크는 지우지 않음 |
| PixelLab | 처음부터 도트 격자 | 옆모습 참고 그림을 못 넣음 | [PIXELLAB_PROMPTS.md](PIXELLAB_PROMPTS.md) |

## 공식 자료와 시트 종류 (2026-11-25)
- 외형 기준: 위키 갤러리 `https://wutheringwaves.fandom.com/wiki/<영문 이름>/Gallery`의 Full Sprite. 동작 참고: 같은 갤러리의 Idle Animation·Resonance Liberation. 기술 이름: 캐릭터 문서의 기술 6종. 받은 공식 이미지는 커밋하지 않는다.

- 받은 시트 검수: 크기·방향(16칸 세로 1024×1536), 윤곽 둘레 색 번짐, Full Sprite와 외형 대조.
