# 시트 프롬프트 (첨탑의 메아리)

이미지 생성 AI(GPT)에 붙여 넣을 도트 시트 프롬프트를 쓰고, 사용자가 만든 시트를 받아 원본 자리에 넣는 일을 한 흐름으로 한다. 사용자는 디자이너다. 프롬프트는 **에셋 보드 HTML**(`npm run board`, 첫 탭은 캐릭터별 지금 에셋, 카드마다 프롬프트 보기)에서 복사하고 고른다. md 문서는 보드가 읽는 데이터일 뿐이니, 사용자에게 md를 읽으라고 하지 않는다.

먼저 읽을 것: `docs/art/ART_PIPELINE.md`(규격·절차), `docs/STATUS.md`(지금 상태), 캐릭터 외형은 `docs/lore/CHARACTER_BIBLE.md`. 외형·무기·기술은 추측하지 않는다.

## 1. 무엇이 비었는지부터
프롬프트를 쓰기 전에 지금 있는 것을 센다. 추측하지 말고 파일로 확인한다.
- 동작 시트: `assets/motion/<id>_<state>.png`, 대기 `assets/<id>_idle.png`. 프레임 수는 `가로/세로`.
- 이미 있는 프롬프트: `docs/art/*_PROMPTS.md`, `art/card-prompts.md`. 같은 키를 두 번 만들지 않는다.
- 빈 것을 표로 보여 주고 이번 범위를 한 번 묻는다(사용자가 이미 정했으면 묻지 않는다).

## 2. 프롬프트 쓰기
- 영어 프롬프트, 한 항목에 복사 블록 하나. 블록 앞에는 한국어로 등급·첨부·용도를 한 줄 적는다.
- GPT 시트 프롬프트는 이 순서로 쓴다: `OBJECTIVE`(무엇을 왜) · `REFERENCES`(첨부마다 역할, 첨부가 유일한 근거이고 안 보이는 부분은 지어내지 않음) · `REQUIREMENTS (must)`(칸별 동작) · `PREFERENCES (optional)` · `CONSTRAINTS`(잠금 문장) · `OUTPUT`(크기·칸) · `VALIDATION`(객관적 검수 항목). 같은 지시를 두 번 쓰지 않고, 쓰기 전에 서로 부딪히는 규칙이 없는지 본다(예: "모든 칸 같은 발 선" ↔ 쓰러짐 칸).
- 문서 안내 글에는 근거를 구분해 적는다: 확인됨(설정 기준표·공식·게임 파일) / 추정(지금 도트를 보고 적음) / 미확인. 받은 결과를 볼 한국어 검수 체크리스트를 문서에 둔다.
- 제목 줄은 보드가 키를 읽는 형식을 지킨다: `### <키>.png · <한국어 이름>`. 키 종류와 들어갈 자리는 `scripts/art-board.cjs`의 `slot()`이 정한다.

| 키 | 원본 자리 |
|---|---|
| `hero_<id>`, `hero_<id>_full`, `hero_<id>_extra` | `art/source-v2/` |
| `enemy_full_<id>` | `art/source-v2/` |
| `cards_<id>`, `battle_*` | `art/source-v2/` |
| `fx_<이름>` | `art/fx-src/` |
| 카드 단품 `<카드id>` | `art/card-gen/` |

- 공명자 외형 문장은 `docs/art/HERO_PROMPTS.md`의 16칸 프롬프트에 확정된 것을 그대로 쓴다. 새로 지어내지 않는다.
- 적의 공격·시전 장면은 `src/js/data.js`의 `EN` 기술 이름에서 가져온다.
- 같은 틀의 프롬프트가 여러 개면 손으로 쓰지 말고 생성 스크립트로 만든다(예: `scripts/motion-prompts.cjs` → `docs/art/MOTION_PROMPTS.md`). 고칠 때도 스크립트를 고쳐 다시 돌린다.
- 새 프롬프트 문서는 `scripts/art-board.cjs`의 `DOCS`와 `docs/README.md`에 등록한다.

### 꼭 넣는 잠금 문장
생성 결과에서 실제로 반복된 문제라서 넣는다. 빼면 같은 문제가 다시 나온다.
- 크기·칸: 이미지 크기(1024×1536 세로, 1024×1024 정사각), 열×행, 칸 사이 선·숫자 없음, 테두리에서 10~12% 여백(칸을 기계로 자르므로).
- 크기 고정: 모든 칸에서 같은 키(칸 높이의 72%), 발이 같은 선. 공명자 7등신, 머리 큰 비율 금지. 숫자만으로는 GPT 대화마다 비율이 달라지니, 공명자 시트는 비율 가이드 `art/guides/hero-16-guide.png`(`node scripts/make-guides.cjs`)를 첨부 3으로 붙이게 한다(파란 선 머리·빨간 선 발·맨 위 띠 머리 1/7, 선은 그리지 않게).
- 외형 기준은 명조 공식 자료(공식 사이트 캐릭터 페이지·공식 위키·인게임 캡처)다. 첨부 1을 공식 이미지로 두고 외형의 기준이라고 쓰며, 지금 도트는 도트 밀도·크기 기준으로만 쓴다. 무기 종류는 설정 기준표를 따른다(증폭기·권총 캐릭터에게 칼 동작을 주지 않는다).
- 도트: 균일한 격자, 1px 윤곽선, 48색 이하, 안티앨리어싱·디더링·붓 질감 없음.
- 배경: 진짜 투명, 체크무늬·바닥 그림자 없음. 투명이 안 되면 단색 초록 #00FF00으로 채우게 한다(GPT는 투명 대신 가짜 체크무늬를 그리는데, 초록은 `unchecker.cjs`가 모서리로 알아보고 정확히 지운다. 캐릭터에 초록이 거의 없어 안전). 이펙트는 단단한 도트 모양, 번지는 빛·외곽 글로우·연기 없음.
- EDGE LOCK: 픽셀은 완전 불투명 또는 완전 투명. 윤곽에 청록·빨강·노랑·흰 테두리나 반투명 그림자 없음.
- 잔상은 쓰지 않는다(흐린 덩어리로 나온다). 속도선은 2px 단색 직선 3줄.
- 방향: 공명자는 오른쪽, 적은 왼쪽.
- 이펙트는 흑백 세 단계(#FFFFFF·#B0B0B0·#505050)로 받고 속성색은 `scripts/make-vfx.cjs`가 칠한다. 한 장으로 6속성을 쓴다. 외부 무료 에셋은 CC0만 쓰고 출처를 `art/fx-src/README.md`에 적는다.

### PixelLab용 (pixellab.ai Character Creator)
캐릭터를 한 번 만들고 동작을 하나씩 붙인다. `node scripts/pixellab-prompts.cjs`가 `docs/art/PIXELLAB_PROMPTS.md`와 비교 기준 `art/pixellab-ref/<id>.png`(커밋 안 함)를 만든다. 고칠 때는 이 스크립트를 고친다. 칸 이름은 **웹 화면 스크린샷(2026-11-20)** 기준이다. 화면이 바뀌면 스크린샷을 받아 다시 맞춘다(문서·API 설명만 보고 칸을 지어내지 않는다).
- 탭 Create from Text. Create from Reference는 정면(South) 그림이 필수라 옆모습 도트는 못 넣는다.
- Character Type Humanoid / Quadruped(네발) / Custom(그 밖), Generation Mode v3, Camera View **Sidescroller**, Detail Highly detailed, Outline. 결과 8방향 중 공명자 East, 적 West.
- Negative·체형 비율·Shading 칸은 없다. 피할 것은 외형 설명 안에 원하는 모습으로 쓴다(최대 2000자).
- 크기는 게임 규격의 정수분의 1: 무료 체험(64px까지) 공명자 64·적 48/64/64, Tier 1 이상 160·96/128/192. 비용은 화면 아래 "Costs N generations"로 확인한다.
- 보드는 PixelLab 항목을 화면과 같은 순서의 단계 카드(탭→Character Type→Mode→Description→Camera→Size→Detail·Outline→Generate→결과→동작)로 그린다. 메모 줄 형식(`Character Type **…** · Sprite Size 무료 N / 유료 N · 방향 … · 비교 기준 `…``)을 바꾸면 `art-board.cjs`의 `it.pl` 정규식도 같이 고친다.
- 동작 화면은 아직 미확인. 받은 결과는 `art/pixellab/<id>/<동작>.png`. 게임 연결은 `dev`.

## 3. 보드로 보여 주기
```
npm run board        # scripts/art-board.cjs로 art/board.html을 만들고 연다
```
보드에서 사용자가 프롬프트를 복사하고, 후보를 지금 그림과 비교해 고른다. 맨 위 탭(GPT 시트 / PixelLab 캐릭터)과 필터(종류: 공명자·적·이펙트·카드·배경·공통 / 상태: 후보 있음·그림 있음·그림 없음, 프롬프트 접기)로 좁힌다. 새 문서는 `DOCS`에 넣으면 종류가 키·제목·`##` 제목으로 자동 분류된다(`kindOf()`). 답변에는 보드의 어느 묶음을 보면 되는지만 적는다. 후보 이미지는 에이전트가 열어 비교하지 않는다(사용자가 보드에서 고른다).

## 4. 사용자가 시트를 올렸을 때
1. **누구·어느 자리인지 먼저 확인한다.** 지금 도트(`assets/enemy_<id>.png`, `assets/<id>.png`)와 나란히 놓고 본다. 요청과 다르거나 모양이 지금 도트와 다르면 적용하지 말고 묻는다(새 디자인일 수 있다).
2. 체크무늬·초록 배경이면(알파 없음) 지운다: `node scripts/unchecker.cjs <입력> <출력>`. 흰 장갑·은색 몸(메카 등)은 `strict`를 붙인다. 이펙트에 둘러싸여 남은 체크무늬 조각은 `box:x0,y0,x1,y1`로 그 범위만 넓게 지운다(예: 파수인 공격 나비). 몸 둘레의 밝은 회색 테두리는 자동으로 벗긴다(어두운 윤곽선에서 멈춤).
   - 토큰 절약: 결과는 이미지를 열지 말고 수치로 확인한다(가장자리 밝은 회색 비율, 테두리 닿음, 색 영역 평균). 이미지는 비교용 잘라낸 것 한 장만 본다. 사용자에게는 채팅에 붙이는 대신 `art/candidates/<키>/`에 파일을 넣어 달라고 권한다.
3. 후보 자리에 둔다: `art/candidates/<키>/upload<번호>.png`.
4. 사용자가 반영을 요청했으면 적용한다: `node scripts/art-board.cjs apply <키> <파일>`. 요청이 없으면 보드에서 고르게 둔다.
5. 받은 시트에서 본 문제(번짐, 잔상, 테두리 색, 칸 침범, 디자인 변경)를 프롬프트 잠금 문장에 반영하고, 끝난 프롬프트는 문서에서 빼서 "받은 시트" 표로 옮긴다.
6. 게임 연결(자르기·재생 코드)이 없는 종류면 그렇다고 말한다. 연결은 `dev` 브랜치 일이다.

## 5. 끝내기
- 브랜치: 프롬프트·에셋 도구는 `art`. 시작할 때 `git merge main`. 커밋하고 `art`에 push한다. `main` 병합은 통합 업무라 사용자가 요청할 때만 한다.
- `docs/STATUS.md`에 한 줄 남긴다. 다시 만들 수 있는 결과물(`art/board.html`, `art/preview-v3/`)은 커밋하지 않는다.
- 공식 이미지는 커밋하지 않는다.
